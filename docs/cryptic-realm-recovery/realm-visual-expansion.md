## Decision: `server/realm_config.ts` is superseded, not finished

Three files had been sitting untracked in the production checkout since
2026-07-20/21. They are preserved verbatim in `5a82df674` and removed in
`7c2d42661`.

`realm_config.ts` was a second implementation of realm body assignment.
`server/realm_visuals.ts` already ships the same capability and is wired, live,
and driving arcforge.moveweight.com:

| | `realm_config.ts` (in-flight) | `realm_visuals.ts` (shipped) |
|---|---|---|
| Targets | class, npc, opponent | `class:` `hero:` `npc:` `mob:` |
| Storage | flat JSON files | DB, revisioned |
| Workflow | overwrite | draft → publish → history |
| Auth | shared secret, hardcoded fallback | `content.read` / `content.edit` |
| Discovery | none | `/api/realm-visuals/:realm/targets` |
| Wired | no | yes |

Two live sources of truth for one piece of state is a defect, so the duplicate
was dropped rather than completed. Three further reasons:

1. **Its data was a regression.** The JSON predates `c518256bd` ("curated
   infernal roster"). Adopting it would have reverted infernal classes from the
   `realm_infernal_class_*` bank to the older `realm_infernal_human_*` bank,
   cut `crypticrealm` from nine mapped classes to one, changed ~7 NPC role
   bodies, and replaced the `hellmaw_*` opponent bank.
2. **It never compiled.** It imported `loadClassVisualConfig` and
   `loadInfernalConfig`; neither exists. These were the only two typecheck
   errors in the repo, which is why it was never registered.
3. **It hardcoded a fallback admin secret.** Dead — nothing referenced the
   module and the value appears nowhere else — but it must not ship.

## Landed: claudecraft creature bank (`c596fc925`)

All 21 claudecraft GLBs registered as `realm_claudecraft_*` visuals, with
`REALM_MOB_FAMILY_KEYS.claudecraft` and `REALM_MOB_DEFAULTS.claudecraft` mapping
beast / humanoid / undead / demon / dragonkin / mudfin onto them.

`elemental`, `spider`, `burrower`, `troll` and `ogre` are deliberately left on
the shared `FAMILY_KEYS` fallbacks: the store has no convincing body for them,
and a wrong body is worse than a generic one.

Clip maps come from each GLB's real animation list. Bodies exporting a single
baked take (`Armature|Unreal Take|baselayer`, or `walking_man` for `mini-orc`)
alias every ClipMap slot to that clip, following `realm_classic_kitty`, instead
of naming clips the GLB does not contain. Presentation only — template ids still
own families, loot, combat and quests.

Guarded by `tests/claudecraft_visual_bank.test.ts` (5 cases), including the
invariant that **every** claudecraft mob resolves to a registered visual key.

## Deployment notes that bit previous sessions

- Public realm domains are served by the **stage-live rings**
  (`/opt/cr-stages/<realm>/live`, e.g. infernal on `:8810`), not
  `/opt/cryptic-realm`. Rebuild that worktree and restart
  `cryptic-realm-stage@<realm>-live`, then poll for the port to bind before
  declaring it up.
- GLBs are gitignored and never travel with code; they ship out-of-band into
  `CR_REALMS_DIR` and are shared across rings.
- Pushes cannot originate in LXC 171 (read-only deploy key). Use the Windows
  bundle relay at `C:\Users\wadei\cr-relay`.
- `tests/recovery_manifest.test.ts` fails by design on any side branch.
